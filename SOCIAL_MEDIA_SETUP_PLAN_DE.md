## 13) Vollautomatisierter Social-Media-Flow (Erstellung + Posting)

### Zielbild
Ein System, das **regelmäßig Inhalte erstellt, freigibt und automatisch auf Instagram/Facebook veröffentlicht** – mit klaren Guardrails für Qualität und Markenstimme.

### Empfohlener Tech-Stack
- **Orchestrierung:** n8n (alternativ Make)
- **Content-Engine:** OpenAI API (Textideen, Captions, Varianten)
- **Asset-Erstellung:** Canva API / Bannerbear / Midjourney-Workflow (optional)
- **Planung & Freigabe:** Airtable oder Notion (Content-Kalender + Status)
- **Publishing:** Meta Graph API (Facebook + Instagram Business)
- **Ablage:** Google Drive/Dropbox (Bild- und Video-Assets)
- **Monitoring:** Slack/Email-Benachrichtigungen + KPI-Sheet

### Automations-Workflow (End-to-End)
1. **Trigger (wöchentlich):** z. B. Montag 08:00 Uhr.
2. **Themenfindung:**
   - zieht 5–10 Content-Ideen aus den definierten Säulen.
   - priorisiert nach Funnel-Stufe (Awareness/Consideration/Conversion).
3. **Content-Generierung:**
   - erstellt Hook, Caption, CTA, Hashtags, Story-Frames, Reel-Skript.
   - generiert je Thema 2 Varianten (A/B).
4. **Brand-Check:**
   - prüft Keywords wie „DSGVO“, „2–4 Wochen“, „Demo“, „B2B“.
   - verbietet unzulässige Claims (regelbasiert).
5. **Freigabeschritt:**
   - „Human-in-the-loop“: Status `Draft -> Review -> Approved`.
   - ohne Freigabe kein Posting.
6. **Auto-Publishing:**
   - postet zum geplanten Slot via Meta API.
   - schreibt URL/Asset/Caption in Log-Tabelle.
7. **Reporting (automatisch):**
   - sammelt Reichweite, Klicks, Saves, DMs.
   - erzeugt Wochenreport mit Top-Posts + Empfehlungen.



### Claude Routines statt n8n/Make – macht das Sinn?
**Kurzantwort:** Ja, **für den Content-Entwurf und interne Aufgaben** kann Claude Routines sehr sinnvoll sein.  
**Für vollautomatisches, verlässliches Multi-Channel-Publishing** bleibt n8n/Make + Meta API meist robuster.

#### Wann Claude Routines ideal ist
- wiederkehrende Redaktionsaufgaben (Ideen, Caption-Varianten, Hook-Listen)
- Zusammenfassungen aus Notizen, Calls, Website-Updates
- Vorqualifizierte Content-Pakete für die manuelle Freigabe

#### Grenzen von Claude Routines (operativ)
- Abhängigkeit von Nutzungs-/Routine-Limits
- Nicht als vollständiger Ersatz für stabile API-Orchestrierung gedacht
- Publishing-Automation Richtung Meta ist in klassischen Workflow-Tools transparenter (Retries, Fehlerpfade, Logs)

#### Empfehlung (Hybrid-Setup = beste Praxis)
1. **Claude Routines** erstellt täglich/wöchentlich Content-Pakete (Texte, Hooks, Varianten)
2. **Airtable/Notion** übernimmt Freigabeprozess (`Draft -> Review -> Approved`)
3. **n8n/Make** übernimmt API-sicheres Scheduling + Posting + Reporting

So kombinierst du die kreative Stärke von Claude mit der Betriebssicherheit von Automations-Workflows.


### Posting-Frequenz (Startkonfiguration)
- **Instagram:** 4 Feed-Posts/Woche, 3 Reels/Woche, tägliche Stories.
- **Facebook:** 3 Posts/Woche + Crosspost von Reels/Carousels.
- **CTA-Rhythmus:** mindestens 2 Conversion-Posts pro Woche.

### Sicherheits- und Qualitätsregeln
- Immer Freigabe-Gate vor Veröffentlichung.
- API-Keys nur im Secret-Store (nicht im Klartext in Workflows).
- Fallback-Mechanismus: bei API-Fehlern Wiederholung + Alert.
- Blacklist für sensible Begriffe/versprochene Garantien.
- Rechtstext-/Impressum-Links in Profilen dauerhaft prüfen.

### Minimaler MVP (in 5 Arbeitstagen)
- Tag 1: Konten/API-Zugänge verbinden

- Tag 3: Generator-Prompts + Brand-Guardrails

## 15) Wichtige Klarstellung: Was Perplexity Comet darf (und was nicht)

### Ja – das soll Comet holen
- Öffentlich verfügbare Informationen zu Marke, Offer, CTA, Positionierung
- Öffentliche Social-Profil-URLs (Instagram/Facebook/LinkedIn/X/YouTube)
- Öffentliche Inhalte für Research (FAQ, Claims, Keywords, Hashtags)

### Nein – das soll Comet **nicht** holen
- **Keine Logins, keine Passwörter, keine Tokens**
- **Keine privaten Account-Daten aus Meta/Facebook/Instagram**
- **Keine Admin-Rechte/Session-Daten**

### Für Posting-Automation zwingend getrennt
- Logins/Token/Berechtigungen kommen **nur** über Meta Business / Graph API Credentials in n8n.
- Perplexity liefert nur den Research-Input (Content-Daten), nicht die Authentifizierung.

### Konkrete Aufgabentrennung
1. **Perplexity Comet:** sammelt öffentliche Daten + strukturiertes JSON
2. **n8n:** verarbeitet JSON, erstellt Captions/Assets, postet via Meta API
3. **Meta Credentials:** regeln sichere Authentifizierung für Facebook/Instagram Posting
